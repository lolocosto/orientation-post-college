# v0.59 — Phase 5 : Nettoyage des fallbacks et correction vues/export

## Principe

Après les phases 1-4, tous les établissements ont obligatoirement un `_id` interne.
Les fallbacks `_id || uai` dans les vues et modals ne sont donc plus nécessaires
et masquaient des bugs potentiels.

---

## Changements

### G1 — `gestion_onglet_resultats.js:1452`

**Avant** :
```javascript
const id = etablissement._id || etablissement.uai;
```

**Après** :
```javascript
const id = etablissement._id;
if (!id) {
    console.warn('[buildEtablissementDetailsHTML] ⚠️ Établissement sans _id:', etablissement.nom || etablissement.uai);
}
```

**Impact** : `isEtablissementFavori(id)` reçoit maintenant `undefined` au lieu d'un UAI si `_id` est absent. Le favori ne s'affichera pas comme actif, mais c'est un cas anormal qui sera loggué.

### G2 — `details_modal.js:85`

**Avant** :
```javascript
const id = etablissementEnrichi.etablissement._id || etablissementEnrichi.etablissement.uai;
```

**Après** :
```javascript
const id = etablissementEnrichi.etablissement._id;
if (!id) {
    console.warn('[DetailsModal] ⚠️ Établissement sans _id:', nom);
}
```

**Impact** : `favoriId` dans `#renderModal()` reçoit `undefined` au lieu d'un UAI. Le bouton favori sera inactif, ce qui est le comportement correct (un étab sans _id ne devrait pas exister).

### Bug pré-existant — `data_education_extraction_controller.js:304`

**Avant** :
```javascript
await this.#databaseService.updateEtablissement(infos.uai, infos);
```

Passait un **UAI** comme premier argument (attendu : un `_id`). L'ancien `updateEtablissement` faisait un `Object.assign` silencieux sur `undefined`. Le nouveau retourne `false` sans rien faire.

**Après** :
```javascript
if (!infos.uai) continue;
const etabs = this.#databaseService.getEtablissementsByUaiSync(infos.uai);
for (const etab of etabs) {
    this.#databaseService.updateEtablissement(etab._id, infos);
}
```

Résout d'abord l'UAI en _id via `getEtablissementsByUaiSync`, puis met à jour chaque établissement correspondant. Applique à tous les étabs partageant cet UAI (enrichissement data.education = données du site physique).

### Conservé tel quel — `gestion_onglet_resultats.js:748`

```javascript
<strong>${etab.nom || etab.uai}</strong>
```

C'est un **fallback d'affichage**, pas un identifiant. Si le nom est absent, afficher l'UAI est acceptable pour l'UX. On le garde.

## Bug identifié (non corrigé — hors périmètre)

`data_education_extraction_controller.js:309` :
```javascript
await this.#databaseService.updateDispositif(section.uai, { sports: section.sports });
```

`updateDispositif(libelle, updates)` attend un **libellé**, pas un UAI. Ce code ne fonctionnait probablement déjà pas. À investiguer dans une version ultérieure.
