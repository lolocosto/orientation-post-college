# v0.59 — Phase 2 : Ajout de `etabNom` dans le parser Onisep

## Principe

Chaque relation (diplôme↔établissement, dispositif↔établissement, option↔établissement, spécialité↔établissement) doit porter le **nom de l'établissement** en plus de l'UAI, pour permettre la résolution par clé composite (UAI, nom) au lieu de l'UAI seul.

Les champs source API existaient déjà dans les listes `select` des requêtes ONISEP mais n'étaient pas exploités par le parser.

---

## Changements

### 1. `_parseActionLycee()` — relation diplôme-établissement

**Ajout du champ `etabNom`** dans la relation `diplomes_par_etablissement` :

```javascript
etabNom: action.lieu_denseignement_ens_libelle
      || action.structure_denseignement_ens_libelle
      || null,
```

**Source API** : `lieu_denseignement_ens_libelle` (actions_lycee) ou `structure_denseignement_ens_libelle` (actions_sup).

### 2. `_parseActionLycee()` — enrichissement établissement

**Ajout du champ `etabNom`** dans l'objet `enrichissements_etab` :

```javascript
const etabNom = action.lieu_denseignement_ens_libelle
             || action.structure_denseignement_ens_libelle
             || null;
if (etabNom) enrich.etabNom = etabNom;
```

Permet à `#enrichirEtablissementsDepuisActions` de résoudre par UAI+nom au lieu de UAI seul.

### 3. `_parseActionSup()` — héritage automatique

`_parseActionSup()` délègue à `_parseActionLycee()` → bénéficie automatiquement du `etabNom`.

### 4. `_parseActionDispositif()` — relation dispositif-établissement

**Ajout du champ `etabNom`** dans la relation `dispositifs_par_etablissement` :

```javascript
etabNom: action.lieu_denseignement_ens_libelle
      || action.structure_denseignement_ens_libelle
      || null,
```

### 5. `_parseEnseignementOptionnel2ndeGT()` — relation option-établissement

**Ajout du champ `etabNom`** dans la relation `options2ndeGT_par_etablissement` :

```javascript
etabNom: data.libelle_lieu_de_cours || null,
```

**Source API** : `libelle_lieu_de_cours` (dataset enseignements_optionnels_2nde).

### 6. `_parseEnseignementSpecialite1ereG()` — relation spécialité-établissement

**Ajout du champ `etabNom`** dans la relation `specialites1ereG_par_etablissement` :

```javascript
etabNom: data.libelle_lieu_de_cours || null,
```

**Source API** : `libelle_lieu_de_cours` (dataset enseignements_specialite_1ere).

---

## Cohérence avec le parser CARIF

Le parser CARIF (`carif_oref_parser.js`) portait **déjà** le champ `etabNom` dans ses relations (ligne 474) :

```javascript
etabNom: (f.etablissement_formateur_enseigne || '').trim()
      || (f.etablissement_formateur_entreprise_raison_sociale || '').trim()
      || null,
```

Après cette phase, **tous les parsers** produisent des relations avec `etabNom`.

---

## Impact

- **Aucun impact rétro** : le champ `etabNom` est ajouté mais n'est pas encore consommé par les contrôleurs (ils l'ignoreront tant qu'ils ne sont pas migrés phase 3).
- **Aucun changement de signature** : les méthodes de parsing gardent les mêmes entrées/sorties.
- **Pas de requête API supplémentaire** : les champs étaient déjà demandés dans les `select`.
